## Анализ предметной области информационной системы

**Тема:** Информационная система института для организации учебного процесса

---

## 1. Описание предметной области

Рассматривается информационная система института, предназначенная для хранения и обработки сведений, связанных с организацией учебного процесса.

В институте обучаются студенты, объединённые в учебные группы. Для студентов хранятся основные персональные и учебные сведения. Обучение ведётся по образовательным программам, включающим различные дисциплины.

Преподаватели проводят занятия по дисциплинам у определённых учебных групп. В ходе обучения учитываются результаты выполнения студентами учебных работ и результаты аттестации.

С системой работают студенты, преподаватели и сотрудники института:
- студенты получают информацию о своём обучении и результатах;
- преподаватели работают со сведениями о проводимых дисциплинах и результатах студентов;
- сотрудники института получают и актуализируют информацию об организации учебного процесса.

Данные должны сохраняться в течение всего периода обучения студента. Одни и те же данные могут одновременно использоваться различными пользователями, а доступ к информации зависит от роли пользователя.

---

## 2. Проблема и цель системы

**Проблема.**
Сведения об учебном процессе (студенты, группы, дисциплины, преподаватели, результаты аттестации) хранятся разрозненно — в бумажных журналах, таблицах и локальных файлах. Из-за этого:
- сложно быстро получить актуальную информацию о результатах студента
- данные дублируются и могут противоречить друг другу
- нет единого разграничения доступа по ролям
- затруднён контроль успеваемости и учебной нагрузки.

**Цель.**
Разработать информационную систему для централизованного хранения и обработки сведений об организации учебного процесса, обеспечивающую разграничение доступа по ролям и оперативный доступ к результатам обучения.

**Область применения.**
Система предназначена для использования в институте (деканат, кафедры, преподаватели, студенты) для ведения учебного процесса, учёта успеваемости и информирования участников.

## 3. Анализ предметной области

### 3.1. Основные объекты

| Объект | Назначение | Основные характеристики |
|--------|------------|--------------------------|
| **Студент** | Хранение сведений об обучающемся | ID, ФИО, дата рождения, номер зачётной книжки, группа, форма обучения, статус |
| **Учебная группа** | Объединение студентов | ID, название, курс, направление, год набора |
| **Образовательная программа** | Описание программы обучения | ID, название, уровень, направление, срок обучения |
| **Дисциплина** | Учебный предмет | ID, название, код, объём часов, семестр, программа |
| **Преподаватель** | Проведение занятий | ID, ФИО, должность, кафедра, учёная степень |
| **Занятие** | Единица учебного процесса | ID, дисциплина, группа, преподаватель, дата, время, вид (лекция/практика) |
| **Учебная работа** | Задание для студента | ID, дисциплина, вид (КР, реферат, лабораторная), срок сдачи, описание |
| **Результат аттестации** | Оценка знаний студента | ID, студент, дисциплина, вид аттестации, оценка, дата |
| **Пользователь** | Учётная запись для входа | ID, логин, пароль, роль, связанный объект (студент/преподаватель/сотрудник) |
| **Роль** | Определение прав доступа | ID, название, описание прав |

### 3.2. Связи между объектами

- **Студент** принадлежит одной **Учебной группе** (M:1).
- **Учебная группа** обучается по одной **Образовательной программе** (M:1).
- **Образовательная программа** включает множество **Дисциплин** (M:N).
- **Преподаватель** проводит занятия по **Дисциплинам** (M:N).
- **Занятие** проводится для **Группы** по **Дисциплине** **Преподавателем**.
- **Студент** выполняет **Учебные работы** (M:N).
- **Результат аттестации** связывает **Студента** и **Дисциплину**.
- **Пользователь** имеет одну **Роль** (M:1) и связан с **Студентом**, **Преподавателем** или **Сотрудником**.

## 4. Пользователи и роли

| Роль | Назначение | Основные действия |
|------|------------|-------------------|
| **Студент** | Просмотр информации о своём обучении | Просмотр своих дисциплин, результатов аттестации, учебных работ; просмотр расписания; изменение контактных данных |
| **Преподаватель** | Работа со сведениями о дисциплинах и результатах | Просмотр своих дисциплин и групп; выставление и редактирование оценок; создание учебных работ; просмотр успеваемости студентов |
| **Сотрудник института** | Актуализация данных учебного процесса | Управление студентами, группами, дисциплинами, программами; формирование отчётов; назначение преподавателей |
| **Администратор** | Управление системой и доступом | Управление пользователями и ролями; настройка прав доступа; резервное копирование; просмотр журнала действий |

## 5. Функциональные требования

- **FR-01.** Система должна позволять пользователю авторизоваться и определять его роль.
- **FR-02.** Система должна обеспечивать разграничение доступа к данным в зависимости от роли.
- **FR-03.** Система должна позволять сотруднику института добавлять, редактировать и удалять сведения о студентах.
- **FR-04.** Система должна позволять сотруднику института управлять учебными группами и образовательными программами.
- **FR-05.** Система должна позволять сотруднику института вести справочник дисциплин и назначать преподавателей.
- **FR-06.** Система должна позволять преподавателю просматривать список своих дисциплин, групп и занятий.
- **FR-07.** Система должна позволять преподавателю выставлять и редактировать результаты аттестации студентов.
- **FR-08.** Система должна позволять преподавателю создавать учебные работы и указывать сроки сдачи.
- **FR-09.** Система должна позволять студенту просматривать свои дисциплины, занятия и учебные работы.
- **FR-10.** Система должна позволять студенту просматривать свои результаты аттестации.
- **FR-11.** Система должна обеспечивать формирование отчётов по успеваемости группы и по нагрузке преподавателей.
- **FR-12.** Система должна обеспечивать хранение данных в течение всего периода обучения студента.
- **FR-13.** Система должна поддерживать одновременную работу нескольких пользователей с разграничением прав доступа.
- **FR-14.** Система должна позволять администратору управлять учётными записями и ролями пользователей.
- **FR-15.** Система должна вести журнал действий пользователей (аудит).

## 6. Концепция информационной системы

**Назначение.**
Система предназначена для централизованного хранения и обработки сведений об организации учебного процесса в институте.

**Основные возможности.**
- Ведение справочников студентов, групп, дисциплин, преподавателей, программ.
- Учёт занятий и учебных работ.
- Учёт результатов аттестации.
- Разграничение доступа по ролям.
- Формирование отчётов.
- Долговременное хранение данных.

**Тип системы.**
Веб-приложение с клиент-серверной архитектурой.

**Основные компоненты.**
1. **Пользователь** — студент, преподаватель, сотрудник, администратор.
2. **Web-интерфейс** — браузерный доступ к системе.
3. **Серверная часть** — бизнес-логика, обработка запросов, разграничение прав.
4. **База данных** — хранение сведений об объектах предметной области.
5. **Модуль аутентификации и авторизации** — вход и проверка прав.
6. **Модуль отчётов** — формирование отчётности.

**Результат использования.**
Пользователь получает актуальную информацию в соответствии со своей ролью: студент — свои оценки и задания, преподаватель — данные для работы с дисциплинами и студентами, сотрудник — инструменты управления учебным процессом, администратор — управление системой.
